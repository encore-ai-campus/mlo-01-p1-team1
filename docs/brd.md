## 1. 배경과 현재 문제

월별 자동차 통계와 FAQ를 사람이 따로 복사·정리하면 실행 범위, 출처, 품질검사와 변경 이력을 같은 방법으로 재현하기 어렵다.

1. FAQ 표준화 - 국내기업(현대자동차, 삼성자동차, )
2. 구간별 차종 등록 현황
    1) 차량 구매 트랜드
3. B2C 타겟의 서비스 이용 시간 및 비용

## 4. In scope

- `STK-FAQ-DATA-001`: 승인된 FAQ 데이터의 수집·정제·품질검사·MongoDB 적재와 출처 이력 관리를 포함한다.
- `STK-CAR-DATA-001`: 승인된 자동차 데이터의 수집·표준화·품질검사·MySQL 적재와 출처 이력 관리를 포함한다.
- `STK-PIPE-OPS-001`: FAQ·CAR 파이프라인의 수동·예약 실행, 중복 방지, 실패 판정, 안전한 재실행과 로그 관리를 포함한다.
- `STK-DQ-REV-001`: 원천·스키마·품질검사·처리 건수·실행 로그와 요구사항 증거 검토를 포함한다.


## 5. Out of scope

- `STK-FAQ-DATA-001`: 승인되지 않은 FAQ 수집, 접근 제한 우회, FAQ 생성·추천·분석 기능은 제외한다.
- `STK-CAR-DATA-001`: 차량·소유자 개인정보, 실시간 데이터 처리, 자동차 통계 예측·분석 기능은 제외한다.
- `STK-PIPE-OPS-001`: 사용자용 UI·API·대시보드와 Production 수준의 HA·DR·24시간 관제는 제외한다.
- `STK-DQ-REV-001`: 원본·DB 데이터의 직접 수정과 외부 기관의 법적·규제 감사 수행은 제외한다.


## 6. 업무 규칙·제약·가정
- `BR-CON-001`: 품질검사를 통과한 CAR 데이터는 MySQL에, FAQ 데이터는 MongoDB에 저장한다.
- `BR-CON-002`: 승인된 원천과 범위의 데이터만 수집하며, 원천·스키마가 불명확하면 적재하지 않는다.
- `BR-CON-003`: credential·private endpoint·개인정보는 문서·Git·로그에 기록하지 않는다.
- `BR-CON-004`: 동일 입력을 재실행해도 데이터가 중복되지 않으며, 실패한 실행은 마지막 성공 상태를 변경하지 않는다.
- `BR-ASM-001`: 각 데이터 담당자가 수집 원천·필드·품질 기준을 확인할 수 있다고 가정한다.
- `BR-ASM-002`: live source를 사용할 수 없으면 동일한 구조의 검증용 fixture를 사용한다.
